# Buổi 51 — CQRS: command, query và dispatcher tự viết

> **Thời lượng:** 150 phút
> **Chặng:** Buổi 49–53 · **Tag kết quả:** `b53-ddd-cqrs`
> **Buổi này chạm:** `Application/Common/Messaging/*`, `Orders/Commands/*`, `Orders/Queries/*`, `Application/DependencyInjection.cs`, `OrdersController.cs`, `OrderHub.cs`

---

## Mục tiêu

1. Phân biệt **command** (ghi, có thể bị từ chối) và **query** (đọc, không đổi gì) — chữ "CQ" của CQRS.
2. Viết command/query dạng `record` bất biến + **1 handler cho 1 use case**.
3. Hiểu và **tự viết** dispatcher (`ISender.Send`) — biết MediatR làm gì bên trong.
4. Controller/hub chỉ phụ thuộc `ISender`.
5. Đăng ký handler tự động bằng quét assembly.

---

## Mở đầu — vì sao không dùng MediatR? (15 phút)

Thảo luận [ADR 0003](../adr/0003-cqrs-dispatcher-tu-viet.md) mục 4:

- MediatR là thư viện phổ biến nhất cho mẫu này. Từ **bản 13** chuyển sang **giấy phép thương mại**; bản 12.x vẫn Apache-2.0 nhưng là nhánh cũ.
- Phần cốt lõi ta cần (`Send`, pipeline, notification) chỉ ~120 dòng → **tự viết** để hiểu, không phụ thuộc giấy phép.
- Bài học nghề: trước khi thêm gói NuGet, **đọc giấy phép** (MIT/Apache-2.0 thoải mái; thương mại/"source-available" phải hỏi công ty).

> **Giảng viên nói:** "Dùng thư viện không sai. Nhưng hôm nay ta viết lại để lần sau đọc stack trace của MediatR hay Wolverine các bạn biết nó đang làm gì."

## Bước 1 — `IRequest<T>`, `ICommand<T>`, `IQuery<T>` (10 phút)

```csharp
public interface IRequest<TResponse>;
public interface ICommandBase;                                        // nhận diện command (buổi 52 dùng)
public interface ICommand<TResponse> : IRequest<TResponse>, ICommandBase;
public interface IQuery<TResponse> : IRequest<TResponse>;
```

Kiểu kết quả nằm **trong** interface → `sender.Send(new GetOrderByIdQuery(...))` biết trả `OrderDto?` lúc biên dịch.

## Bước 2 — `IRequestHandler<TRequest, TResponse>` (10 phút)

1 handler = 1 use case, constructor chỉ inject đúng thứ use case đó cần. `ICommandHandler`/`IQueryHandler` chỉ là tên gọi rõ nghĩa.

## Bước 3 — `Sender`: dispatcher tự viết (30 phút)

Bài toán: `Send<TResponse>(IRequest<TResponse> request)` — lúc biên dịch chỉ biết `TResponse`; kiểu request thật (`PlaceOrderCommand`?) chỉ biết **lúc chạy**. Không viết thẳng `GetService<IRequestHandler<???, TResponse>>()` được.

```csharp
var wrapper = (RequestWrapper<TResponse>)Wrappers.GetOrAdd(request.GetType(),
    static (reqType, resType) => Activator.CreateInstance(typeof(RequestWrapper<,>).MakeGenericType(reqType, resType))!,
    typeof(TResponse));
return wrapper.Handle(request, services, ct);
```

`RequestWrapper<TRequest, TResponse>` biết **đủ 2 kiểu** → `services.GetService<IRequestHandler<TRequest, TResponse>>()` bằng code generic bình thường. `MakeGenericType` chỉ chạy **1 lần** mỗi kiểu request (cache `ConcurrentDictionary`).

Live-code từng dòng, rồi đặt breakpoint trong `RequestWrapper.Handle` và gọi `POST /api/orders` trên Scalar để xem call stack.

⚠️ **Lỗi hay gặp:** `GetRequiredService` khi chưa đăng ký handler → `InvalidOperationException` khó hiểu của DI. Ở đây báo rõ: "Chưa đăng ký handler cho X (quên AddApplication()?)" — test `Send_WithoutHandler_ThrowsHelpfulError`.

## Bước 4 — `PlaceOrderCommand` (25 phút)

`Orders/Commands/PlaceOrder.cs` — **vertical slice**: command + validator (buổi 52) + handler trong 1 file.

```csharp
public sealed record PlaceOrderCommand(int? UserId, string CustomerName, string PhoneNumber,
    IReadOnlyList<OrderLineRequest> Items, string? DiscountCode, PaymentMethod PaymentMethod,
    string? CardNumber, string? Note) : ICommand<OrderDto>
{
    public static PlaceOrderCommand From(PlaceOrderRequest request, int? userId) => ...;
}
```

- `UserId` lấy từ **token** ở controller, là 1 trường của command (không phải từ body).
- Handler: tra món (`GetByIdsAsync`), tra mã giảm giá, `Order.Create → AddItem → ApplyDiscount → Pay`, `orders.Add`, `SaveChangesAsync`. **Không** gọi notifier — `OrderPlaced` lo (buổi 50).
- So sánh với `OrderService.PlaceAsync` (b48): logic giống, nhưng giờ là 1 class riêng, test riêng (`OrderHandlerTests`).

## Bước 5 — `ChangeOrderStatusCommand`, `CancelOrderCommand` (15 phút)

Handler chỉ 4 bước: `GetAsync` → kiểm tra `user.CanAccess(order.OwnerId)` (không → `NotFoundException`, chống IDOR) → gọi method aggregate → `SaveChangesAsync`. Luật nghiệp vụ **không** nằm ở handler.

## Bước 6 — Query: `GetOrderByIdQuery`, `GetMyOrdersQuery` (10 phút)

Query handler **không** dùng `IOrderRepository`/aggregate — đọc qua `IOrderReadStore` (cổng đọc, trả DTO; cài đặt projection ở buổi 53). Đây là chữ "S" (Segregation): đường ghi và đường đọc tách nhau.

## Bước 7 — Controller + hub chỉ còn `ISender` (15 phút)

```csharp
public class OrdersController(ISender sender) : ControllerBase
{
    public async Task<ActionResult<OrderDto>> Place(PlaceOrderRequest request, CancellationToken ct)
    {
        OrderDto dto = await sender.Send(PlaceOrderCommand.From(request, this.User.GetUserId()), ct);
        return this.CreatedAtAction(nameof(this.GetById), new { id = dto.Id }, dto);
    }
}
```

`OrderHub.WatchOrder` gửi **cùng** `GetOrderByIdQuery` với `GET /api/orders/{id}` → 1 luật IDOR cho 2 cửa vào. `OrderService` bị xóa.

## Bước 8 — Đăng ký tự động (10 phút)

`AddApplication()`: quét assembly, kiểu nào implement `IRequestHandler<,>`, `IDomainEventHandler<>`, `IValidator<>` thì `AddScoped(interface, type)`. 1 class implement nhiều interface (`OrderQueryHandlers`) → đăng ký cho từng interface.

Test canh: `EveryRequest_HasRegisteredHandler` (Application.Tests) và `EveryRequest_HasExactlyOneHandler` (ArchitectureTests).

## Exit ticket

1. Command khác query thế nào? Cho mỗi loại 1 ví dụ trong CyberCafe.
2. Vì sao `Sender` cần `MakeGenericType` và vì sao chỉ gọi 1 lần cho mỗi kiểu?
3. Vì sao `UserId` là trường của command chứ handler không tự đọc `HttpContext`?
4. MediatR 13+ có gì khác 12.x về giấy phép? Ảnh hưởng gì khi chọn thư viện cho dự án công ty?

**Đáp án gợi ý:** (1) Command đổi trạng thái, có thể bị từ chối (`CancelOrderCommand`); query chỉ đọc (`GetBaristaBoardQuery`). (2) Kiểu request chỉ biết lúc chạy; dựng wrapper generic 1 lần rồi cache để các lần sau không tốn reflection. (3) Application không biết ASP.NET Core; command là dữ liệu đầy đủ → gửi được từ hub, job, test. (4) 13+ là thương mại (cần license); 12.x Apache-2.0 — phải kiểm tra giấy phép trước khi đưa vào sản phẩm.
